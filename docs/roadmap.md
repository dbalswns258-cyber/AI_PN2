# 단계별 개발 계획

일정이나 자동화율은 실제 자료 검증 전 확정하지 않는다. 단계별 통과 근거를 먼저 만든다.

| 단계 | 목표 | 통과 조건 |
|---|---|---|
| 1 현재 | 독립 2D 엔진 + 로그인 웹 + 합성 검증 | 계산·권한·원본/이력·실제 브라우저 흐름 확인 |
| 2 실제 급수 1장 | 한 층/화장실 구간의 사용자 기준 확정 | 단위·관경 변경·중복/블록·미지원 목록, 구간/관경별 기존 산출 비교 |
| 3 범용성 확인 | 다른 설계사무실 도면 검증 | 개발에 쓰지 않은 도면에서 같은 기준으로 차이 원인 추적; 사용자 허용오차 합의 |
| 4 기존 도구 연결 | LISP 출력과 공통 데이터, MQC 매핑 | 실제 제품/버전·공식 입력 기능 확인, 품목·규격·단위·공종·산출식·할증 검증 |
| 5 산출 확대 | 입상·기구별 보완, 부속·보온, 다른 공종 | 승인된 기준 버전, 직접/보완 구간 중복 방지, 기준별 회귀 테스트 |
| 6 판독 지원 | 문자/범례/기호/연결/다른 도면의 후보 | 사람이 수정·확정하는 동일 검토함; 실제 정답 데이터로 오탐/누락 측정 |
| 7 BIM MEP | 목적에 따라 IFC 또는 Revit 모델 | 층고·Z·구배·연결·관경·패밀리/부속 출처 검증, 모델/산출 교차 검증 |
| 8 운영 확대 | 사용자/프로젝트 권한과 배포 | PostgreSQL·관리형 파일 저장·HTTPS·작업 큐·백업/복구·운영 관측 검증 |

## MQC 의사결정 순서

1. 제조사·제품명·버전과 공식 문서를 확인한다. 현재 미확정이다.
2. 공식 API/연동 기능을 먼저 검토한다.
3. 지원되는 파일 가져오기, 다음으로 표 붙여넣기를 확인한다.
4. 대안이 없을 때만 PC 화면 자동화를 검토한다. 화면·버전 변경에 대한 재검증이 필요하다.

엑셀 내보내기는 가져오기 가능성의 증거가 아니다. 내부 파일을 추측해 수정하지 않는다. MQC 최종 결과와 자체 결과의 할증·반올림·품목/규격 대응을 표로 확인한다.

## BIM 의사결정

Revit 편집용 모델이 필요한지 IFC 교환 파일이 필요한지 먼저 정한다. Revit/AutoCAD 로컬 자동화에는 해당 프로그램·실행 환경·라이선스 조건이 필요하다. IFC 라이브러리만 설치했다고 BIM 연결과 실제 부속 생성이 해결되는 것은 아니다. 승인된 기본값은 사용자 승인 출처와 함께 기록한다.

## 운영 전 남은 일

실제 자료 검증, 표준 도면층/품목/산출 기준 승인, 안전한 외부 공개 배포, 계정 관리/공유 권한 UI, 자료 백업·복구 시험, 대용량 DXF 격리 처리, 원본 CAD 시각 검증, MQC 최종 엑셀 파일 보관 화면은 아직 남아 있다. 첫 버전 결과로 발주·납품 자료를 자동 확정하지 않는다.
