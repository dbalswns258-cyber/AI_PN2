# 요구사항과 첫 검증 범위

## 목적과 역할

대전·세종·충남교육청 학교 기계설비 공사의 위생·가스·환기·냉난방·공기순환기 적산을 장기 대상으로 한다. 실무자가 도면 의미와 적산 기준을 판단하고, 프로그램은 그 판단을 데이터·재현 가능한 계산·검토 가능한 출력으로 바꾼다.

현재 업무: 외부 DWG → AutoCAD 산출 LISP로 선택 선 길이 산출 → 부속·기구·장비·보완 검토 → MQC 입력 → 산출서·집계표·내역서 엑셀 출력 → 최종 검토. 기존 LISP·MQC를 대체한다고 가정하지 않는다.

목표 업무: 원본 보관 → 의미 판독 → 표준 설비 데이터 → 표준 CAD → 필요 3D 정보를 확보한 BIM → 버전이 있는 산출 기준 적용 → 검토·확정 → 검증된 MQC 전달 → 최종 자료 보관.

## 자료 확인과 결정 상태 (2026-10-07, 한국 시간)

- 초기 저장소: `index.html` 한 개, 패키지·테스트·서버 없음. 원본 파일은 수정하지 않음.
- 작업 공간: 실제 DWG/DXF, LISP, 산출서, MQC 문서 없음.
- 사용자 답변: MQC 제조사·제품·버전·가져오기 기능은 미확정으로 진행.
- 사용자 답변: 실제 도면 단위·반올림 기준도 미확정으로 진행.
- 따라서 업무 합격 기준, 허용오차, 자동화율, 개발 기간은 확정하지 않음.

## 첫 버전의 완료 범위

| 요구 | 구현 |
|---|---|
| 독립 Python 엔진 | `takeoff/`, CLI 실행 가능 |
| DXF 추출 | 모델 공간 LINE, LWPOLYLINE, 일반 2D POLYLINE; TEXT/MTEXT; INSERT 메타데이터 |
| 수동 판독 | 객체별 급수·호칭지름·근거·상태, 선택적 층·재질·구역·공사 구분 |
| 산출 | 확정 객체의 XY 중심선 평면 길이, 관경별 합계; 단위·반올림 명시 |
| 표준 CAD | 별도 DXF에 확정 객체의 도면층·색상·선종류 적용, 원본 handle 추적 |
| 엑셀 | 집계·객체 근거·미확정/제외·실행 기준, CLI 비교 시 차이 시트 |
| 웹 | 실제 로그인/POST 로그아웃, 소유자 권한, 프로젝트 생성/수정/조회 |
| 저장 | SQLite DB + 저장소 외부 파일, 원본 UUID 버전·SHA-256·이전 버전 연결 |
| 작업 관리 | 별도 작업자, 대기/진행/완료/실패, 명시적 재시도 최대 3회, 중복 요청 억제 |
| 검토와 이력 | 미확정 필터, 객체별 편집, 이전/변경 값·사용자·시각·수정 번호 |
| 조회·다운로드 | 첫 공종 급수, 관경/구역별 필터, 별도 결과 DXF/XLSX/JSON 권한 검사 |
| 검토 참고 | PDF/이미지의 보호된 미리보기, DXF는 객체 번호·좌표·원본 다운로드 |

## 판단 규칙

표시 표준화(도면층 등)와 의미 표준화(계통·규격·연결 등)는 다르다. 모르는 의미는 빈 값으로 남긴다. 원본 레이어·색상·문자·블록은 참고 근거이며 자동 확정 조건이 아니다. 향후 AI 후보도 사람이 수정·확정하는 같은 검토 경로를 이용한다.

도면·범례·관경 문자·기호·연결 경로·다른 도면의 대응을 함께 활용하는 판독은 후속 단계다. 첫 버전은 사람의 근거 서술을 보존하며 자동 교차 판독은 하지 않는다.

## 후속 요구와 미구현

입상·기구 연결 기준 보완, 부속 공제/가산, 할증, 보온, 전체 공종, 자동 AI 판독, 표준 블록 변환, DWG/AutoCAD PC 연결, BIM(Revit 편집 모델 또는 IFC 교환 모델 선택 필요), MQC 입력, MQC 최종 엑셀 보관 UI, 팀별 권한/초대/공유, 온라인 비밀번호 재설정은 후속이다. 현재 업로드는 DXF·PDF·PNG·JPG로 제한되며 실제 엑셀 보관 UI는 추가해야 한다.

## 다음 실제 자료 검증에 필요한 정보

미확정 답변을 반복 요청하지 않는다. 실제 자료를 준비하는 단계에서 원본 DXF와 알려진 치수, 대표 구간·관경, 대응 산출서, 적용 LISP, MQC 공식 가져오기 설명을 확인한다. 한 설계사무실의 자료로 규칙을 맞춘 뒤 다른 설계사무실 도면을 별도 검증 세트로 사용한다.
