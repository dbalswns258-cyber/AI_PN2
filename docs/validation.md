## 합성 도면 구성과 결과

`python -m takeoff.cli sample <새 폴더>`로 언제든 생성한다. 실제 학교나 실제 도면을 모사한 정확도 데이터셋은 아니다.

| 합성 구간/객체 | 지정 | 예상/실제 |
|---|---|---|
| (0,0)→(3000,4000) 직선 | 급수 DN20, mm | 5 m |
| 2000 + 1000 직각 폴리선 | 급수 DN25, mm | 3 m |
| 현 2000, bulge=1 반원 | 급수 DN20, mm | π m |
| 첫 직선과 방향만 반대인 중복 | 이유와 함께 제외 | 0이 아닌 **제외 상태**, 집계 안 함 |
| 미지정 직선 | 미확정 | 집계 안 함 |
| 문자·블록·원·높이 변경 선 | 참고/미지원, 미확정 | 집계 안 함 |

관경별 합산 후 소수 3자리 사사오입: **DN20 8.142 m, DN25 3.000 m**. 확정 3개, 제외 1개, 미확정 5개. 합성 예시 기준으로만 통과했다.

## 회귀 검사에서 확인한 위험 지점

- 같은 입력·기준에서 동일한 계산 결과, 수작업 반올림 누적 방지, 원본 해시 변경 거부.
- 단위/확인 근거 누락 거부, 출력 축척 미적용, 닫힌 폴리선 마지막 구간과 기존 POLYLINE bulge 처리.
- 기울어진 좌표계·높이 변경·블록 내부·원 등 미지원 객체 확정 거부.
- 중복이 미검토이거나 이중 확정이면 계산 보류, 부분 겹침을 임의 합치지 않음.
- 별도 DXF 생성, 원본 바이트와 객체 handle 보존, 원본 레이어 이름 충돌과 true color 처리.
- 엑셀의 미확정/제외 항목, 사용자 입력을 엑셀 수식으로 실행하지 않음.
- 기존 산출 CSV의 객체+관경 대응·차이·미대응 항목 표시; 허용오차 임의 확정 없음.
- 실제 비밀번호/세션 로그인, CSRF, POST 로그아웃, 로그인 제한, 사용자 간 프로젝트/파일/작업 접근 차단.
- 잘못된 업로드·다른 프로젝트 버전 연결 차단, 원본 버전 보존, 확인 변경 이력, 오래된 수정 충돌.
- 작업 중복 요청, 실행 점유 중복, 실패/재시도 한도, 중단 작업 감지, 실행 시 확인 스냅샷 보존.

## 실제 자료 검증 절차 (아직 수행 안 함)

1. 원본 DWG와 별도 저장 DXF의 대응·해시·버전을 등록한다. 단위는 알려진 치수로 확인하고 출력 축척과 구분한다.
2. 한 층/화장실 급수 구간과 객체별 관경 변경 지점을 지정한다. 미지원·블록·외부참조·특수 객체 목록을 확인한다.
3. 기존 LISP/MQC 산출과 객체 또는 실무 구간의 대응표를 작성한다. 단위·부속·보완·할증 범위가 같은지 맞춘다.
4. 총합뿐 아니라 구간별·관경별 차이를 비교한다. 차이가 나는 객체 번호·좌표·미확정/제외 이유로 원인을 추적한다.
5. 중복/끊긴 선/곡선/부분 겹침/블록 변환/도면 누락을 검토한다. 실제 AutoCAD에서 표준 DXF를 열어 원본과 비교한다.
6. 사용자가 사례에 근거해 허용오차·합격 기준을 정한다. 테스트 코드의 수학적 오차 허용값을 업무 허용오차로 가져오지 않는다.
7. 기준 개발에 사용하지 않은 다른 설계사무실의 도면으로 반복한다.

## 미검증/미구현과 운영 한계

실제 도면 판독 정확도, 실제 기존 산출 차이, 다른 설계사무실 검증, AutoCAD 표시의 완전한 왕복 보존, 기존 LISP 연결, MQC 입력/출력, Revit·IFC BIM, PC 연결 프로그램, 런타임 AI, 다중 작업자·공개 호스팅·백업 복구는 검증하지 않았다. 합성 비교 CSV 검사는 실무 산출서와의 비교가 아니다.

현재 인스턴스의 설치·실행과 저장된 재사용 설정은 별개다. 환경 설정 초안 저장만으로 게시 또는 새 클라우드 작업에서의 복원이 검증된 것은 아니다. 첫 사용자 계정은 본인이 `createsuperuser`로 생성해야 하며 브라우저 검사의 임시 계정은 남기지 않는다.

## 클라우드 설정과 보관된 예시

현재 인스턴스에서 `bash scripts/dev.sh worker`와 `bash scripts/dev.sh web`을 실제 실행했다. 내부 HTTP 요청으로 로그인 폼/CSRF와 CSS 응답을 확인했다. 앞선 임시 DB 브라우저 검사에서 실제 기능도 검증했다.

환경 설정 초안의 **install_script**, **start_skill** 저장이 서버 응답 `status=saved`로 확인되었다. 설치 스크립트는 재실행 검증한 `scripts/install.sh`를 호출한다. 시작 안내에는 기존 checkout 사용, 프로세스 재시작, 실제 기능 검사, 계정 생성, 실제 자료 미검증 상태를 기록했다. 네트워크 허용 목록이나 비밀값 요구는 추가하지 않았다. 환경 설정에서 검토·저장 후 사용자가 게시해야 하며 게시/새 작업 복원은 아직 확인하지 않았다.

재확인 가능한 합성 입력과 실제 생성 출력은 저장소 밖 `/workspace/ai-pn2-data/examples/first-run/`에 보관했다. `output/`에는 별도 DXF, 엑셀, JSON이 있다. 실제 공사 자료가 아니다. 저장소 안에는 생성 DXF/XLSX/사용자 DB가 없는 것을 최종 확인했다.

## 공개 배포 준비 검증 (추가)

외부 접속 요청에 따라 Gunicorn 26.2.0, WhiteNoise 6.12.0, Render 배포 명세, 단일 서비스 실행 관리, 영구 저장 경로, 테스트 프로젝트 분류, 백업 스크립트를 추가했다. 기존 index.html은 계속 보존한다.

- 전체 자동 테스트: **44개 통과**, 실패 0, 건너뜀 0. 추가 검사는 상태 확인, HTTPS 프록시 전달·CSRF·보안 쿠키, 테스트/업무 프로젝트 구분이다.
- `python3 scripts/browser_smoke.py --python /workspace/ai-pn2-venv/bin/python --production`: **통과**. 실제 Gunicorn/WhiteNoise와 별도 작업자로 로그인·업로드·검토·산출·다운로드를 실행했다.
- 같은 데이터 디렉터리로 운영 프로세스를 중지/재시작한 후 계정·로그인 세션·프로젝트·결과 보존과 원본 파일 SHA-256 일치를 확인했다.
- 실행 중 SQLite snapshot + 참조 원본/결과 + 서명 키를 백업하고 별도 디렉터리로 복원했다. 복원한 상태에서 다시 로그인 세션·프로젝트·결과·원본 해시를 확인했다.
- 운영 HTTPS 설정의 `manage.py check --deploy`에는 HSTS의 하위 도메인 전체 적용/브라우저 사전 등록을 켜지 않은 경고 2개(W005/W021)가 있다. 소유·정책을 확인하지 않은 도메인 범위에 강제로 적용하지 않았으며 인증/CSRF/HTTPS redirect/보안 쿠키 항목 경고는 없다.
- 실제 호스팅 계정은 아직 연결되지 않았다. 이 검사는 로컬 운영 프로세스 검증이며 Render의 실제 디스크·HTTPS URL·외부 접속 성공을 의미하지 않는다. 배포 계정 연결 후 [배포 안내](deployment.md)에 따라 외부 검증을 계속해야 한다.
